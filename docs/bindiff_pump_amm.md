### Function alignment (2-stage; tightened to avoid over-pairing)
1. **Stage 1 (identity):** pair by exact normalized-content hash, a register/branch-insensitive hash (pure codegen), and by Anchor dispatcher discriminator - **only REAL sha256-derived 8-byte discriminators** (high entropy). Synthetic/structured ids (leading-zero MSB or >=3 zero bytes) are rejected as identity evidence; those functions go through stage-2 only.
2. **Stage 2 (fuzzy):** greedy **k-gram containment** (k=6, mnemonic skeleton) of the leftovers, length window [0.7, 1.43], **containment >= 0.75**, and a **prologue-compatibility gate** (first 8 normalized mnemonics must align) so two functions with incompatible frame setups are never fused. Highest-score-first, each function used once.
3. Stage-2 pairs are classified by the per-pair logic. Only functions with no qualifying twin stay MISSING/EXTRA - an honest non-correspondence, not a double-count.
