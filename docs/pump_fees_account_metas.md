# `pump_fees` account surface, read from the deployed bytes

Every Anchor handler is generated from an accounts struct: a `try_accounts` frame pulls one `AccountInfo` per declared field off a slice iterator, then raises one error per violated constraint. This page records that surface for all 31 deployed handlers of `pump_fees`: the `AccountInfo` record itself, the fetch sites, and every constraint raise site with its code, its name, the account it names, and the check that guards it. Generated by `tools/account_metas.py`; the raw records are in `maps/pump_fees_account_metas.json`.

## The AccountInfo record

The shared fetch helper advances an iterator by **48** bytes and raises **3005** when it runs out, which fixes the record's stride and its field offsets:

| field | offset | read by |
|---|---:|---|
| `key` | 0 | key compares (2001 has_one, 2012 address, seeds) |
| `lamports` | 8 | lamport reads |
| `data` | 16 | account data (discriminator + Borsh body) |
| `owner` | 24 | owner compares (2004 / 3007) |
| `rent_epoch` | 32 | rent-exempt constraint (2005) |
| `is_signer` | 40 | signer constraint (2002) / AccountNotSigner (3010) |
| `is_writable` | 41 | mut constraint (2000) / AccountNotMutable (3006) |
| `executable` | 42 | executable constraint (2007) |

The iterator itself is a two-word cursor `{ptr@0, remaining@8}`: a fetch checks `remaining`, decrements it, takes `ptr` and stores `ptr + 48` back.

Of the constraint sites, 74 are program-address derivations with the seed vector recovered (literal prefix + the key/length seeds), and 6 compare the account key against a 32-byte constant (the published program and mint keys resolve to `pump`, `pump_amm`, `WSOL`, `tokenkeg`, ...).

Every raise site that names an account carries its name as `(ptr, len)` in the error record, so the slot is read from the name and matched against the instruction's account list in the published IDL: 213 of 213 named sites resolve to a declared slot. Sites that name nothing are the associated-token and token-program comparisons the program builds for derived addresses; they are reported by code and address only.

The IDL also declares, per account, a fixed `address` or a `pda` seed list. Measured against those declarations: **4 of 4** fixed-key compares hit the declared address, and **57 of 64** recovered seed vectors have the declared seed count and literal prefixes.
